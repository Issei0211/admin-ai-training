# Create PR Skill (Pull Request 本文作成)

このスキルは、現在の Git 差分やコミット履歴を解析し、チームの標準フォーマットに従って GitHub の Pull Request (PR) 本文（Description）テキストを自動作成するための作業手順書です。

## スキルの目的
* 開発者やレビュアーが 30 秒で変更内容、背景、検証状況を正確に把握できるようにする。
* PR 本文の記述表記や粒度をチーム全体で標準化する。

## 実行ルール・指示
1. 開発者から「PR本文を作成して」「PRの概要を書いて」等の指示を受けた際、まず `git status` を確認すること。次に、`gh pr view --json baseRefName --jq '.baseRefName'` 等で現在のブランチに対応する PR の target branch を解決して `<base>` とし、解決できない場合は `develop` を `<base>` として使用すること。そのうえで、`git diff <base>...HEAD`（または未コミットの変更差分）と `git log <base>..HEAD` を確認・解析すること。
2. 下記の「PR のフォーマット」に厳格に従ってテキストを出力すること。
3. 差分に含まれる軽微なフォーマット修正やタイポ修正は「主な変更点」から除外するか、末尾にまとめて記載すること。
4. **出力はそのまま GitHub の PR 説明欄（Description）に貼り付けられる純粋なマークダウンテキストのみ**とし、不要な前置きや補足メッセージ（例:「PR本文を作成しました」等）は含めないこと。

---

## PR のフォーマット

以下のマークダウン構造に従って作成してください。

## 目的

[変更の背景・目的を記述]

## 概要

- 何をしたのか（1〜2行で簡潔に）
- 変更の背景・目的

## 主な変更点

- **[機能/コンポーネント名]**: 変更内容の要約
- **[API/DB]**: 変更内容の要約

## 影響範囲・破壊的変更

- [既存機能への影響や、環境変数の追加など注意点があれば記載（なければ「なし」）]

## テスト・検証内容

- Codex/手動で実行したテスト内容
